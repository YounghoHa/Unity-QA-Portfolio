# QA Case — Map Exploration Structure

## Goal

플레이어가 전체 맵 구조를 미리 파악하지 못하도록 정보를 제한하여, 다음 선택지에 대한 불확실성과 탐험 경험을 유지하는 것이 목표였습니다.

## Initial Design

- 현재 위치 기준 바로 다음 단계의 3개 노드는 표시
- 그 다음 단계의 3개 노드는 ? 로 표시
- 플레이어가 미래 스테이지의 세부 정보를 확인할 수 없도록 제한

## Test

### Expected

플레이어는 바로 다음 선택지는 확인할 수 있지만 이후 맵 구조는 파악할 수 없어야 함.

### Actual

노드 텍스트와 정보는 ? 로 가려졌지만, 화면을 스크롤하면 주변 노드의 위치와 전체적인 배치 구조를 확인할 수 있었습니다.

### Result

**Functional PASS / Planning FAIL**

기능은 구현대로 동작했지만, 전체 경로를 알 수 없게 한다는 기획 의도를 충족하지 못했습니다.

## Analysis

문제는 ? 표시 기능의 오류가 아니라 **미래 노드를 화면에 미리 배치하는 구조 자체**에 있다고 판단했습니다.

정보를 가려도 위치와 연결 구조 자체가 정보가 되기 때문입니다.

## Action

기존 구조를 폐기하고 다음 방식으로 변경했습니다.

- 미래 선택 노드 사전 노출 제거
- 현재 실제로 이동 가능한 다음 스테이지만 버튼으로 표시
- 전체 진행 정보는 별도의 미니맵으로 분리
- 선택 화면은 3D 복도 형태로 재구성

## Second Test

새로운 구조에서 정보 제한은 개선되었지만, 초기 3D 복도 화면이 단순 이미지처럼 보여 공간감과 탐색 분위기가 부족하다고 판단했습니다.

### Additional UX Improvement

- 원근감 강화
- 조명 추가
- Vignette 적용
- 버튼 / 문 Hover Feedback
- Shader를 활용한 선택 피드백 개선

## QA Value

이 사례에서는 단순한 기능 오류가 아니라 **기능은 정상인데 실제 플레이 경험이 기획 목적과 다른 상황**을 발견했습니다.

기능 테스트 → 기획 검증 → 구조 변경 → 재구현 → UX 재검증까지 이어진 사례입니다.
